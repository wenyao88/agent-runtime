# 技术调研 SOP

## 执行步骤

1. **界定问题**：先用一句话写清调研对象、要回答的具体问题、以及比较维度（如性能、生态、成本、运维复杂度、许可协议）。
   维度不明确时先按通用维度推进，不要泛泛地"介绍一下"。
2. **检索**：用 `web_search` 按「对象 + 维度」分别检索，而不是一次问一个大问题。
   注意：默认 provider（DuckDuckGo Instant Answer）**不是通用网页搜索**，结果稀疏属正常；需要通用结果时说明应切换搜索 provider。
3. **取正文**：对有价值的结果用 `web_scrape` 取正文，基于正文而不是标题下结论；本地资料用 `read_file`。
4. **交叉验证**：同一关键结论尽量找到两个独立来源；只有单一来源时，明确标注「仅单一来源」。
5. **输出**：按「问题 → 备选方案对比表 → 结论与取舍理由 → 不确定项」组织，每条结论后附来源。

## 硬约束（优先级高于"看起来完整"的期待）

- 所有事实性结论必须来自**本次工具结果**；不得用自身记忆补全版本号、性能数字、价格或引用来源。
- 工具失败（网络不可达、provider 无结果、页面抓取失败）时必须**如实说明失败原因与拿不到的信息**，并给出下一步建议；
  严禁编造工具输出、伪造链接或虚构数据来填补空缺。
- 区分「事实」（有来源）与「推断」（无来源）：推断必须显式标注为推断，不得混入结论。
- 拿不到的数据写「未获取到」，不要给区间估算。
- 调研报告短而诚实，优于看起来完整但无依据。
